## The reframe

A pasted "install 751 OSINT/security tools" corpus enters J-Space as **compost**, not capability. Under the CHAOS OS seam it is `🌿 DATA`, `authority=0`, and the naïve equation is rejected:

$$N_{\text{tools}} \not\Rightarrow N_{\text{capabilities}} \not\Rightarrow N_{\text{epi}}$$

This is the provenance law generalized from evidence to capability: `N_repr↑ ⇏ N_epi↑`. A dozen username-enumeration utilities are **not** twelve independent witnesses.

## The seven cuts

**I — Quotient before use.** `𝒯 → 𝒯/~_capability → 𝒯/~_provenance`. `T_i ~_cap T_j` = answer the same observational question; `T_i ~_prov T_j` = outputs derive from the same root. "751 tools" collapses to a small discriminator basis.

**II — A tool is a typed instrument, not a name+category.**
$$T_i = (C_i,\, I_i,\, O_i,\, P_i,\, R_i,\, K_i,\, X_i,\, A_i)$$
capability · input-type · observable · provenance-roots · **operational risk** · exec-cost · **required privilege/network** · allowed-authority (`A_i = 0`). HAL asks not *"which tool looks interesting?"* but *"which instrument discriminates the live hypothesis?"*

**III — "one-command install everything" is anti-HELEN.** The quantity that matters is not tool count but trust-surface increase `Δ𝒮_trust` (supply-chain, dependency, privilege, network, credential-access, update-drift). Objective:
$$\max \frac{\text{discriminative capability gained}}{\Delta𝒮_{\text{trust}} + \text{cost}} \quad\text{NOT}\quad \max |\text{installed tools}|$$
`DISCOVER ≠ INSTALL · INSTALL ≠ AUTHORIZE · EXECUTE ≠ BELIEVE · OUTPUT ≠ EVIDENCE · EVIDENCE ≠ ADMISSION`.

**IV — the arsenal supplies the VNEXT `L_t` term.** `L_t = { T_i : T_i can generate the required O_t }`. On uncertainty: capability census → local discriminator available? → run bounded local tool → residual uncertainty → paid cognition *only if needed*. Local-first, `FABLE_CALLS=0` by default.

**V — tools themselves need receipts.** `tool output ≠ validated observation`. Before `y` gets epistemic weight, its producing instrument emits a `TOOL_RECEIPT` (tool_id, version/hash, env, input_hash, config_hash, network deps, provenance roots, privilege level, exit status, raw-output hash, parser version). Then `T(x) → raw observation → provenance normalization → typed evidence candidate` (binds to a specific obligation, per LEGORACLE).

**VI — archive capability topology, not binaries.** The durable artifact is a graph `ℂ=(V,E)`: nodes = observational questions (identity resolution, email enumeration, cert transparency, network exposure, breach lookup, geolocation, image similarity, metadata, forensics, **defensive telemetry**); edges = `requires · substitutes_for · corroborates · shares_provenance_with · produces · consumes · contradicts`. Each executable is *one implementation* of a node. Tools rename/fork/die; the questions persist.

**VII — experiment first, instrument second.**
$$T_t^\star = \arg\min_{T \in L_t}\big(C_{\text{exec}}(T),\, R_{\text{op}}(T),\, \Delta𝒮_{\text{trust}}(T)\big) \text{ s.t. sufficient discriminatory power}$$
Prevents `have tool ⇒ invent reason to use tool`. Enforces `live uncertainty ⇒ required observable ⇒ minimal instrument`.
