## Structural extractions (topology only)

### S1. HIERARCHICAL NAME EXPANSION (42 from 4)

The Tetragrammaton has 4 letters. The "Mah" expansion spells
each letter's name, yielding 10 letters. The sub-sub-spellings
expand to 28 more. Total: 4 + 10 + 28 = 42.

**Structure**: a tree with branching factor determined by letter
names. The root has 4 children. Each child expands by its own
spelling rules. Three levels of expansion produce the full name.

**HELEN mapping**: The governance status palette has 8 base
glyphs. Each glyph governs a namespace (GOVERNANCE_STATUS,
INTERACTION_VERBS, CONQUEST_BULLETIN_STATES). The
CROSS_NAMESPACE_REUSE register documents where the same glyph
has divergent meanings across namespaces. This is a two-level
expansion: glyph → (namespace × meaning) pairs. The 42-letter
structure suggests a third level is structurally available:
glyph → namespace → context-specific rendering rule.

**The number**: 42 = 14 × 3 = 7 × 6. The 14-section division
(each of 3 letters) maps to HELEN's existing structure only if
we note that 7 × 6 = 42 and HELEN has exactly 7 INTERACTION_VERBS.
This is a coincidence, not a mapping — recorded for completeness,
not as evidence.

### S3. FOUR-MODE INTERACTION TAXONOMY

The Hekspakat system defines four interaction modes:

| Mode | Direction | Emphasis |
|---|---|---|
| INVOKATION | inward | sigil scrying — connect unconscious to conscious |
| EVOKATION | outward | mantras/calls — express intent outward |
| TRANSVOKATION | bidirectional | simultaneous inward+outward — flow state |
| SUBVOKATION | ambient | automatic — always running, asleep or awake |

**HELEN mapping**: This maps directly to HELEN's four-mode
product map (from HELEN_OS_V2_USER_CENTRIC_UX.md):

| HELEN Mode | Hekspakat analog | Structural correspondence |
|---|---|---|
| FOCUS | INVOKATION | inward attention on a single source object |
| WITNESS | EVOKATION | outward observation, recording what happens |
| ORACLE | TRANSVOKATION | bidirectional — query and receive |
| TEMPLE | SUBVOKATION | ambient exploration, always running beneath |

The correspondence is not forced — the Hekspakat taxonomy
distinguishes modes by directionality (inward/outward/both/
ambient), and HELEN's four modes make the same distinctions:
FOCUS is inward-directed attention, WITNESS is outward-directed
recording, ORACLE is bidirectional query, TEMPLE is ambient
exploration that runs beneath the other modes.

**This is the strongest extraction in this batch.** Two
independent systems (a grimoire interaction taxonomy and an AI
companion UX architecture) converge on the same four-mode
partition because the directionality axis is forced by the
interaction physics: you can attend inward, project outward,
do both simultaneously, or let the background process run.
There is no fifth mode.
