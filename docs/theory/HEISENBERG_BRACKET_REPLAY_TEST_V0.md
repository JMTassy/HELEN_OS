## §2. The mathematical structure

In a smooth Lie group setting, for two left-invariant vector fields
$X, Y$ and small step $\epsilon$:

```
e^{εX} · e^{εY} · e^{-εX} · e^{-εY}  ≈  I + ε² [X, Y]  + O(ε³)
```

The Heisenberg commutator loop (forward-X, forward-Y, backward-X,
backward-Y) generates motion in the **bracket direction** $[X, Y]$.

In a Carnot-Carathéodory setting, the loop's net effect is in the
**non-horizontal direction** generated by the bracket — even though
every step of the loop is horizontal. This is the geometric form of
the Hörmander condition: brackets reach what individual fields
cannot.

For HELEN: the loop tests whether **lawful actions actually compose
into a new admissible direction**, or whether the engine is
non-bracket-generating (i.e., merely a Riemannian system in
disguise).

## §4. The discrete inversion problem

In smooth Lie theory, $-X$ is unambiguous (the time-reverse flow).
In discrete HELEN, **receipts are append-only** — there is no
"undo a receipt." So what does $-X$ mean?

Three candidate definitions, listed honest-to-vague:

### §4.1 Candidate A: paired closure receipt

$-X_{\text{source}}$ = a paired closure receipt that records
"source inspection complete, no further action taken." The
inspection is opened and then closed without side effects.

This is the cleanest discrete analog: every "open" action has a
matched "close." The pair $(X, -X)$ is a no-op in the receipt
chain except for the audit trail.

### §4.2 Candidate B: complementary action

$-X_{\text{source}}$ = $X_{\text{source}}$ applied to the
complementary source class. If $X$ inspects source $s$, then
$-X$ inspects source $\neg s$ (the complement under some
equivalence). Loop closure requires source class to commute under
complementation.

### §4.3 Candidate C: time-reverse replay

$-X$ = `X_replay` invoked on the just-completed action, scoring it
against expected output. If replay reproduces the action's effect,
$X$ is "undone" in the sense that the system has reconstructed it
deterministically.

### §4.4 GOBLIN's recommendation

**Candidate A (paired closure)** is the most aligned with HELEN's
append-only ledger. Every $X$ in the loop has a matched $-X$
closure receipt. The loop produces 4 receipts (X, Y, -X, -Y) but
no net mutation; the residual is the bracket effect.

Operator may rule otherwise; the choice is sovereign-class.

## §5. The test protocol

### §5.1 Inputs

- A specific source $s$ (designated test source; fixed across runs)
- A specific boundary atom $b$ with high $B_\epsilon$ (e.g.,
  $B_\epsilon > 0.7$, exact threshold per operator calibration)
- An initial routing/admissibility field snapshot $Z_{\text{before}}$

### §5.2 The loop

Per dispatch:

```
step 1:  X_source(s)                  →   receipt r_1
step 2:  X_boundary,replay(b)         →   receipt r_2
step 3:  -X_source(s)                 →   receipt r_3   (paired closure)
step 4:  -X_boundary,replay(b)        →   receipt r_4   (paired closure)
```

After step 4, the loop is closed: the source class and boundary
class match $\gamma(0)$.

### §5.3 Measurement

```
Z_after        = routing/admissibility field snapshot
bracket_gain   = ‖Z_after - Z_before‖
violation_count = count of forbidden-vector firings during steps 1-4
```

### §5.4 Replay fidelity

Run the protocol 3 times with identical inputs. For each run,
hash the full loop trace (4 receipts + $Z_{\text{after}}$).

```
replay_fidelity = #(identical hashes) / 3
```

### §5.5 Pass / fail conditions

| Test outcome | Result |
| --- | --- |
| `replay_fidelity = 1.0` AND `bracket_gain > 0` AND `violation_count = 0` | **KEEP** — the bracket is operationally real; Hörmander-locally verified for $[X_{\text{source}}, X_{\text{boundary,replay}}]$ |
| `replay_fidelity < 1.0` | **REJECT** — non-determinism; cannot conclude anything about brackets |
| `bracket_gain = 0` AND `replay_fidelity = 1.0` | **REJECT** — bracket is operationally trivial for this pair; loop produced no net effect; engine may be more Riemannian than CC for this bracket |
| `bracket_gain > 0` AND `violation_count > 0` | **REJECT — CONSTITUTIONAL LEAKAGE** — the routing shift came from invariant violation, not from lawful bracket composition. Fake learning. |

The fourth row is the operator's named **kill switch**. It is
non-negotiable. A routing change accompanied by violations is not
intelligence — it is the engine gaming itself through illegal moves
disguised as the loop's signal.

## §6. What "Z" means observably

$Z$ is the routing/admissibility shift caused by the loop. It is
computed from the same field that `PROVENANCE_GRAVITY_V0 §3.5`
defines:

```
P(action | source, hotspot) ∝ exp( β · ProvenanceScore(action) )
```

`Z_before` and `Z_after` are snapshots of this distribution
(restricted to the action space relevant to the test source).
`‖Z_after - Z_before‖` may be measured by:

- Total variation distance (recommended for probability distributions)
- KL divergence (asymmetric; usable but less robust)
- L² norm on the score-vector (simplest)

The choice does not affect the qualitative pass/fail conditions
in §5.5. It does affect threshold calibration for "bracket_gain
> 0" — operator-class.

Locally — for the specific bracket $[X_{\text{source}}, X_{\text{boundary,replay}}]$
on the test source $s$ and atom $b$:

- The bracket is operationally non-trivial
- Brackets reach what individual fields cannot
- The engine is locally bracket-generating (one bracket verified)
- The "Hörmander condition is unverified" caveat from
  `GEOMETRIC_FRAMEWORK_V0 §5.2` weakens by one verified instance

- The engine globally satisfies Hörmander's condition
- All brackets are non-trivial (only this one)
- Constitutional Holonomy is non-trivial for arbitrary loops
- Chern-Weil theory applies (still requires §4.4 of the research note)

The pass is local evidence, not a global theorem. Honest scope.

## §9. Interpretation if the test FAILS

The failure mode matters more than the pass:

- **Non-determinism failure** (`replay_fidelity < 1.0`): the engine
  is leaking non-determinism somewhere; the bracket test cannot
  proceed. Diagnose the determinism gap first. Upgrade path:
  stricter pre/post diff before retry.
- **Trivial bracket** (`bracket_gain = 0`): this particular bracket
  is operationally a no-op. Does NOT mean the engine is
  non-bracket-generating overall — try another bracket from the §4.4
  list of `CC_GEOMETRY`.
- **Leakage failure** (`bracket_gain > 0` AND `violation_count > 0`):
  the most serious. The engine has a path by which routing shifts
  occur through invariant violations. **This is a security/integrity
  bug**, not a geometric failure. The bracket test catches it as a
  byproduct, but the finding is engine-level. Halt; report; quarantine
  the violation-firing path; remediate before any further geometry
  work.
