## GENEALOGIST as a promotion lattice (mini type-system)

GENEALOGIST's contract is a type-checker, not an oracle: **classify the relation, never promote it.** Every relation claim carries two typed fields, and rises in status ONLY when an additional witness is supplied.

    RELATION_TYPE ∈ { ANALOGY, ANTECEDENCE, INTERPRETATION, ATTRIBUTION,
                      INFLUENCE, TRANSMISSION, IDENTITY, NONE, UNKNOWN }
    SUPPORT_LEVEL ∈ { OBSERVED, PLAUSIBLE, SUPPORTED, DEMONSTRATED, CONTRADICTED, UNKNOWN }

**Hard rules (the forbidden type-promotions):**

    ANALOGY        ⊬ INFLUENCE
    ANTECEDENCE    ⊬ TRANSMISSION
    ATTRIBUTION    ⊬ AUTHORSHIP
    INTERPRETATION ⊬ ORIGINAL_MEANING
    SUPPORTED      ⊬ DEMONSTRATED

**Promotion lattice — each rung needs a strictly stronger witness:**

    OBSERVED similarity        → STRUCTURAL_ANALOGY          (witness: shared pattern)
    STRUCTURAL_ANALOGY         → POSSIBLE_INFLUENCE          (witness: compatible chronology + plausible contact channel)
    POSSIBLE_INFLUENCE         → DEMONSTRATED_TRANSMISSION   (witness: explicit citation | documentary chain | attested transmission)

A claim starts at the weakest type it earns and may not skip a rung. Missing witness ⇒ HOLD at the current rung — never fail-open upward.

Input `{ claim, source_A, source_B, provenance_roots, chronology, explicit_citations, known_transmission_links }`
→ Output `{ RELATION_TYPE, SUPPORT_LEVEL, MISSING_WITNESS, ANCESTRY_STATUS ∈ {NONE,POSSIBLE,SUPPORTED,DEMONSTRATED,UNKNOWN}, COUNTEREVIDENCE }`.
