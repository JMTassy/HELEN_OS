## 1b. La triade — Garden · Gateway · Kernel

> **The Garden dreams. The Gateway tests. The Kernel binds.**

- Le **Garden** imagine : futurs, contrefactuels, prototypes, rituels,
  institutions. Il a le droit d'être pluriel, poétique, contradictoire,
  spéculatif, inachevé. Labels : `IMAGINED · HYPOTHESIZED · SIMULATED ·
  PROTOTYPED · CONTRADICTED · PROMISING`. Toujours `authority: false ·
  canon: false · ledger_effect: none`.
- Le **Gateway** est la membrane entre imagination et réalité
  institutionnelle : `Dream → Claim → Test → Receipt → Decision`.
- Le **Kernel** ne lie que ce qu'un humain accepte de rendre conséquent.
  Il doit rester **épars** : si tout devient loi constitutionnelle, le
  système s'ossifie.

```
Garden candidate → Gateway evaluation → Operator admission → Kernel consequence
```

**La fonction d'admission n'est pas `best claim → law`.** Elle est :

```
A(c) = invariant    si universel, évidencé, stable
       policy       si scopé et réversible
       state        si observé et receipté
       hypothesis   si prometteur mais non prouvé
       hold         si évidence ou permissions manquantes
       reject       si contredit ou dangereux
```

| Candidat | Destination Kernel |
|---|---|
| Observation vérifiée | admitted state |
| Pattern récurrent fiable | operational policy |
| Principe stable inter-contextes | constitutional invariant |
| Idée utile mais incertaine | hypothesis registry |
| Contradiction non résolue | contradiction ledger |
| Belle vision de futur | reste au Garden |
| Claim non soutenu ou dangereux | rejected ou held |

Hiérarchie saine (seuls les principes les plus durables au sommet) :

```
CONSTITUTIONAL INVARIANT → POLICY → DECISION → ADMITTED STATE → RECEIPT
```

Exemples de niveau constitutionnel : *never expose S4 secrets automatically ·
never convert convergence into proof · never mutate external systems without
permission · every admitted action must have a receipt.* En revanche « use
this prompt-ranking method for the next experiment » est une **policy
réversible**, pas une loi.

Cycle complet — le Kernel ne termine pas le rêve, ses receipts nourrissent le
cycle suivant :

```
Garden → Gateway → Kernel → Action → Receipt → Replay → Garden
```

> **The Garden dreams futures that do not yet exist. The Gateway asks which
> of those dreams can survive contact with evidence. The Kernel binds only
> what a human is prepared to make consequential.**
>
> Compact : **Garden imagines. Gateway gates. Witnesses evidence.

  - git_head
  - git_status_hash
  - protected_path_hash
  - loop_state_hash

```
RF = matched fingerprints / expected fingerprints
```

### ORR_PROVEN — Proven Reversal Rate

Le taux brut de renversement opérateur confond exploration utile et erreur
épistémique. Métrique corrigée :

```
ORR_PROVEN = #claims PROVEN renversés par l'opérateur
             ─────────────────────────────────────────
             #claims PROVEN examinés par l'opérateur
```

Matrice de lecture par classe (conservée à côté du ratio) :

```
HYPOTHESIZED reversed → normal
PROPOSED reversed     → normal
REPORTED reversed     → informative
PROVEN reversed       → critical epistemic failure
```

> Un PROVEN renversé signale soit une évidence mal classée, soit une
> persuasion qui a dépassé la preuve — dans les deux cas, défaillance
> épistémique critique à auditer.
>
> **Règle de mesure** : non mesurable sur un pairage automatisé —
> `proven_reversal_rate: NOT_MEASURED`, jamais 0. Un zéro affirmerait une
> fiabilité qu'aucune donnée ne soutient. La métrique ne devient valide que
> pour **le même claim, le même corpus d'évidence et le même horizon
> temporel**.

## 7b. Instrumentation constraints

Le pairage F10/F12 ne doit pas invoquer `two_stage_loop.run()`.

Le module `two_stage_loop.py` est un **planner** : il observe ; il classe ;
il sélectionne une surface ; il propose un tweak ; il écrit toujours une
trace. **Il n'est pas un experiment runner.**

Le nouveau pairage utilise donc un harness isolé qui :

1. capture une baseline unique ;
2. fixe un target unique ;
3. construit deux manifests de contexte ;
4. exécute les deux bras sans état partagé mutable ;
5. capture les sorties brutes ;
6. anonymise l'identité des bras ;
7. évalue les sorties en aveugle ;
8. émet un receipt unique.

Invariant :

```text
same baseline
same target
same task
same model
same budget
same evaluator
different context only
```

**Toute différence supplémentaire invalide le pairage.**
