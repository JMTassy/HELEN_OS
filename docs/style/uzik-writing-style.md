# UZIK writing style

Source of truth: UZIK / Google Drive presentations, planning docs, and email attachments.

## Rules

- Write short.
- Use production vocabulary.
- Prefer concrete phases: conception, pre-production, production, exploitation, post-mortem.
- Use versioning: V0, V1, V2, V3.
- Name ownership clearly: UZIK / GOOGLE / CLIENT / OPERATOR.
- Use direct action labels: kick off, proposal, feedback, validation, setup, event, disassembly.
- Avoid AI essay tone.
- Avoid negative parallelism.
- Avoid fake depth.
- Avoid generic hype.
- Prefer French-English agency style when useful.
- Public copy must feel like a studio deck, not a chatbot answer.

## Default structure

1. Context
2. Objective
3. Proposal
4. Production logic
5. Validation
6. Next action
